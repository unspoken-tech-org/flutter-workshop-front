# Branches

| Change | From | Name | Goes into |
| --- | --- | --- | --- |
| Item of a planned wave (`planos/INDEX.md`) | `feature/onda-<N>` | `<type>/<desc>` (commit type), local only | `feature/onda-<N>` by local `git merge --no-ff`, no PR |
| Wave integration | `main` | `feature/onda-<N>` | `main` by one PR, at the end of the wave or at a checkpoint |
| Multi-PR feature outside a wave (only when the user asks) | `main` | `feature/<name>` | `main`, once, when complete |
| Part of that feature | `feature/<name>` | `feat/<name>-<part>` | `feature/<name>` by PR |
| Single-PR change outside a wave | `main` | `<type>/<desc>` | `main` by PR |
| Prod bug, `main` releasable | `main` | `fix/<desc>` | `main`, then patch tag |
| Prod bug, `main` not releasable | `release/X.Y`, cut from the prod tag | `fix/<desc>` | `release/X.Y`, patch tag, then merge into `main` |
| Bug only inside a feature or wave | its `feature/*` | `fix/<desc>` | that `feature/*`, no tag |

- Names in kebab-case. A wave or feature spanning API and front uses the same
  `feature/*` name in both repos.
- `release/X.Y` only when the user asks (see `releases.md`).
- `feature/*` is shared: merge `origin/main` into it weekly and push, never
  rebase it. A sub-branch may be rebased only before it is merged or its PR
  opens.
- `main` and `release/*` take changes only through PRs; `feature/*` also
  accepts direct pushes. Rulesets block force pushes on all three, and moving
  or deleting `v*` tags.
- Merged branches can be deleted. To find a bug, `git bisect --first-parent`.

## Merging a wave item into `feature/onda-<N>`

The orchestrating agent merges, without asking, once all of these hold:

1. In the item's worktree: the repo's full check (tests, lint, build) passes
   and the item's *Pronto quando* evidence is collected. An item with a `🧑`
   gate waits for the user's confirmation.
2. The item branch is up to date with `feature/onda-<N>` (merge it in).
3. `git merge --no-ff <item-branch>` with the message
   `Merge <ID>: <summary>` and a body holding the evidence and the
   `Revalidado contra <base>@<sha>` line. Push `feature/onda-<N>`.
4. CI on that push is green before the next item is merged. Red: fix with a
   commit on `feature/onda-<N>` first.

Merging two items in parallel is fine only when their edited files do not
overlap; a lockfile (`gradle.lockfile`, `pubspec.lock`) is regenerated by the
later item, never hand-merged.
